## 🧱 ЧАСТЬ 1: Структура СУБД, Справочники и Очистка DDL

### 1.1 Логическое распределение 53 боевых полей таблицы `public.tickers`
После проведения генеральной модернизации структура полей главной таблицы распределена по трем изолированным функциональным блокам:
*   **Блок Информационного Паспорта (Входное ядро):** 
    *   `id` (integer, PK) — внутренний уникальный идентификатор.
    *   `symbol` (varchar) — базовый сырой тикер инструмента (например, `AAPL`, `BP`, `BRK.B`).
    *   `exchange_mic` (varchar) — международный ISO-код торговой площадки (`XNAS`, `XLON`, `XAST`).
    *   `currency_id` (varchar) — базовая валюта торгов актива (`USD`, `GBP`, `KZT`).
    *   `provenance` (jsonb) — жесткий маркер происхождения (например, `{"MS_SP500": "2026-06-18"}`).
    *   `ticker_name_map` (jsonb) — кросс-системная матрица кодировок (например, `{"FB": "BRK.B.US", "YAHOO": "BRK-B"}`).
*   **Блок Технических Сигналов (Обновляется `sync_signals_yf.py`):**
    *   `current_price` (numeric) — живая цена, строго приведенная к базовой валюте (для Лондона — в фунтах).
    *   `daily_turnover_usd` (numeric) — дневной оборот торгов в долларах США.
    *   `signal_recommendation` (varchar) — векторный сигнал тренда (`STRONG_BUY` / `SELL` / `NEUTRAL`).
    *   `signal_ema_20`, `signal_sma_50`, `signal_sma_100`, `signal_sma_200` (numeric) — скользящие средние.
    *   `signal_price_to_sma100_pct`, `signal_price_to_sma200_pct` (numeric) — проценты отклонения текущей цены от линий средних.
    *   `signal_rsi` (numeric) — индекс относительной силы (RSI-14).
    *   `signal_macd` (numeric) — трендовая линия MACD (в фунтах/долларах).
    *   `signals_last_synced_at` (timestamp) — штамп времени завершения технического скоринга.
*   **Блок Фундаментального Анализа (Обновляется `sync_fundamentals_yhoo.py`):**
    *   `company_name` (varchar) — официальное англоязычное наименование корпорации.
    *   `sector`, `industry` (varchar) — сектор экономики и индустриальная принадлежность.
    *   `long_business_summary` (text) — текстовое описание бизнеса компании.
    *   `signal_next_report_date` (date) — чистая дата следующего официального релиза (тип `date`).
    *   `revenue_cagr_3y` (numeric) — рассчитанный темп роста выручки за 3 года.
    *   `expense_ratio` (numeric) — комиссия фонда за управление (строго для ETF).
    *   `fundamentals_last_synced_at` (timestamp) — штамп времени фиксации фундаментального профиля.
    *   *15 финансовых колонок здоровья:* `pe_trailing`, `pe_forward`, `peg_ratio`, `price_to_sales`, `price_to_book`, `ev_to_ebitda`, `debt_to_equity`, `current_ratio`, `quick_ratio`, `profit_margin`, `operating_margin`, `return_on_equity`, `return_on_assets`, `dividend_yield`, `payout_ratio`, `free_cash_flow`, `revenue_growth`, `earnings_growth`.

### 1.2 Черный список на удаление из DDL (Утилизация мусора)
Следующие 7 колонок признаны устаревшим балластом ФБ-контура и подлежат физическому удалению из СУБД:
1.  `yahoo_symbol` — Ликвидировано. Роль полностью перешла к JSONB `ticker_name_map->>'YAHOO'`.
2.  `rsi_14` — Ликвидировано. Заменено боевым системным полем `signal_rsi`.
3.  `fb_market` & `fb_exchange` — Ликвидировано. Потеряли смысл после отказа от API Tradernet.
4.  `last_updated_at` — Ликвидировано. Полностью дублирует штамп `fundamentals_last_synced_at`.
5.  `max_ticker_div_yield_pct` — Ликвидировано. Заменено живым эталонным показателем `dividend_yield`.
6.  `isin` — Ликвидировано. Вечный `NULL`, не поставляемый бесплатными API.
7.  `turnover_last_synced_at` — Ликвидировано. Избыточный временной маркер.
*Примечание:* Поле `fb_ticker` в таблице **сохраняется намертво** для обеспечения обратной совместимости с остальными модулями UPort (расчет сделок, бот). Старая таблица `fb_markets` полностью удаляется.

### 1.3 Новая роль Справочника Бирж `public.exchanges`
Таблица `public.exchanges` теперь выполняет двойную критическую функцию:
1.  **Динамический паспорт суффиксов:** В ней хранятся географические суффиксы мировых площадок (колонка `yahoo_suffix`), которые Паспортистка использует для распознавания рынков.
2.  **Шлюз валютных метаданных:** Робот котировок заглядывает в неё по коду `exchange_mic`, вытягивает `currency_id` и связанный мультипликатор из `public.currencies`. Это позволяет автоматически приводить лондонские пенсы к фунтам.

### 1.4 Инструкция по расширению географии (Кейс: Израиль / TASE)
Благодаря дата-центричности Паспортистки, для добавления новой страны и биржи **код Python менять не нужно**. Масштабирование происходит через один SQL-запрос `INSERT`:
```sql
INSERT INTO public.exchanges (mic, exchange_code, yahoo_suffix, currency_id) 
VALUES ('XTAE', 'TASE', '.TA', 'ILS');
```
При залёте тикера `TEVA.TA` Паспортистка динамически вытянет суффикс `.TA`, определит MIC как `XTAE`, валюту как шекель (`ILS`), а сборщик сигналов обсчитает всю шестерку индикаторов в едином мировом стандарте.

## 🟢 ЧАСТЬ 2: Контур А — Централизованная Паспортизация (`utils.py`)

*   **Принцип работы:** Пакетный или одиночный перехват сырых символов, динамическое определение биржи по суффиксам из СУБД, решение коллизий точек/дефисов и фиксация календаря корпоративных отчетов.
*   **Спецификация «Черного ящика»:**
    *   **ВХОД:** Стрипнутый текстовый `symbol` (`AAPL`, `BRK.B`, `BP.L`) + jsonb-строка `provenance`.

        *   `ticker_name_map` — jsonb-матрица с ключами `"YAHOO"` (где `BRK.B` красиво превращен в `BRK-B`) и `"FB"`.
        *   `exchange_mic` — varchar-код площадки (`XNAS`, `XLON`).
        *   `currency_id` — varchar-код валюты торгов (`USD`, `GBP`).
        *   `signal_next_report_date` — чистая дата следующего релиза из календаря Yahoo.
*   **Результат:** Полностью сформированная, зрячая JSONB-карта кодировок, готовая к сквозному использованию.

## 🟢 ЧАСТЬ 3: Контур А.1 — Универсальный Регистратор Источников (`utils.py` -> `manage_provenance`)

*   **Принцип работы:** Атомарное сквозное управление логом происхождения ценной бумаги (`provenance`) на уровне СУБД [Д6]. Контур полностью изолирует логику ведения исторических автографов от интерфейсных модулей и внешних парсеров, защищая базу от перезаписи дат [Д6].
*   **Спецификация «Черного ящика»:**
    *   **ВХОД:** `db_instance` (шлюз СУБД) + числовой `ticker_id` (PK из таблицы `tickers`) + строгий текстовый ключ `source_key` (`"USER_ID=3"`, `"WL_ID=7"`, `"MS_SP500"`) + маркер действия `action` (`"add"` / `"remove"`) [Д6].
    *   **ВЫХОД В СУБД (Управляемые поля):** `provenance` (тип `jsonb` в таблице `public.tickers`) [Д6].
*   **Результат:** 
    *   При `action="add"`: Ювелирное вживление нового ключа [Д6]. Если ключ залетает впервые, Postgres жестко фиксирует текущий `static timestamp` с таймзоной системы. Если ключ уже существовал — срабатывает SQL-барьер на базе оператора `?`, полностью блокируя затирание первоначальной исторической даты [Д6].
    *   При `action="remove"`: Атомарное вырезание указанной пары ключ-значение через Postgres-оператор `-` во время чистки базы «дворником», без затрагивания автографов других пользователей или индексов [Д6].
*   **Архитектурная ценность:** Полная легализация понятия «Глобальный интерес инвестора» без раздувания базы виртуальными портфелями-пустышками (вроде 9999). Возраст интереса к любой инвест-идее теперь хранится навечно в едином справочнике `tickers` [Д6].

## 🔵 ЧАСТЬ 4: Контур Б — Глобальный сборщик котировок (`sync_signals_yf.py`)

*   **Принцип работы:** Пакетный экспресс-скоринг Universe эшелонами по 50 акций. Полный отказ от тяжелых Колец в СУБД. Скрипт одним сетевым кликом вытягивает годовой массив (`period="1y"`) сразу для всей пачки, выпрямляет `pd.MultiIndex` и запускает векторную математику.
*   **Спецификация «Черного ящика»:**
    *   **ВХОД:** Массив тикеров из базы, имеющих заполненную JSONB-карту `ticker_name_map`.
    *   **ВЫХОД В СУБД (Заполняемые поля):** `current_price` (в фунтах/долларах), `daily_turnover_usd` (пересчитанный в доллары США через `currency_rates`), сигнал `signal_recommendation`, скользящие средние `signal_ema_20`, `signal_sma_50`, `signal_sma_100`, `signal_sma_200`, проценты отклонения `signal_price_to_sma100_pct`, `signal_price_to_sma200_pct`, осциллятор `signal_rsi` и тренд `signal_macd`. В поля `fb_market` и `fb_exchange` пишется системный штамп источника `'YAHOO_GLOBAL'`. Фиксируется время `signals_last_synced_at`.
*   **Результат:** Одинаковая глубина теханализа по 6 показателям для любой географии (США, Европа, Казахстан) без календарных коллизий (Yahoo сам вырезает выходные и праздники из истории).

## 🟣 ЧАСТЬ 5: Контур В — Робот Фундаментала (`sync_fundamentals_yhoo.py`)

*   **Принцип работы:** Ночной интеллектуальный сборщик 18 финансовых метрик по схеме «Умного постотчетного триггера» и «Размазывающего фонового щита» через `UNION`.
*   **Спецификация «Черного ящика»:**
    *   **ВХОД:** Список тикеров, набранный двухконтурной выборкой СУБД.
    *   **ВЫХОД В СУБД (Заполняемые поля):** Текстовые поля `company_name`, `sector`, `industry`, `long_business_summary`, 15 числовых коэффициентов здоровья, а также вычисленный в оперативной памяти `revenue_cagr_3y` и `expense_ratio` (для ETF-фондов). Обновляется штамп `fundamentals_last_synced_at`.
*   **Результат:** Сверхточечное обновление P/E и PEG ровно через 48 часов после реального мирового релиза компании, дополненное комиссиями для всех мировых фондов.
*   **Архитектурные защиты:**
    *   *Защита от выходных дней:* В субботу и воскресенье робот блокирует фоновый щит, если постотчетная очередь пуста, полностью разгружая сеть.
    *   *Дросселирование нагрузки:* Жесткий лимит `LIMIT 20` плавно размазывает обновление сотен пустых акций после чистки на 1.5 месяца по 20 штук в сутки, полностью исключая риск бана IP-адреса.

## 🛠️ ЧАСТЬ 6: Спецификация Системных Модулей, Параметров и Связей

### 6.1 Карта Внутренней Инфраструктуры Проекта (Внешние кастомные модули UPort)
Система работает в монолитном взаимодействии четырех внутренних Python-модулей ядра:
1.  **`/root/UPort/database.py` (Модуль СУБД):** Наш кастомный драйвер `db_sys`, осуществляющий пуловое подключение к PostgreSQL, экранирование кавычек и выполнение атомарных транзакций через метод `execute_query`.
2.  **`/root/UPort/utils.py` (Ядро утилит):** Содержит генератор пакетных эшелонов `create_echelons` (возвращает кортеж `yield echelon_idx, batch`, требующий явной распаковки), таймер выполнения процессов `timer` и центральную функцию Паспортистки.
3.  **`/root/UPort/site_connectors/sync_signals_yf.py`:** Глобальный конвейер котировок и 6 технических индикаторов.
4.  **`/root/UPort/site_connectors/sync_fundamentals_yhoo.py`:** Ночной робот постотчетного фундаментала.

### 6.2 Глобальный Конфигуратор параметров (`/root/UPort/config.py`)
Все управляющие лимиты вынесены из тела скриптов в единый файл настроек:
*   `CHUNK_SIZE_SIGNALS = 50` — размер пакетной пачки акций в эшелоне.
*   `PAUSE_SIGNALS_SEC = 1.5` — вежливая задержка между эшелонами для защиты Rate Limit.
*   `CRITICAL_SPLIT_PCT = 40.0` — барьер автоматического самозалечивания сплитов.
*   `FUNDAMENTALS_LIMIT_DAILY = 20` — суточный лимит размазывающего фонового щита.
*   Файл **`/root/UPort/.env`** хранит скрытые ключи: пароли доступа к БД PostgreSQL и технические API-ключи брокеров для паспортистки.

### 6.3 Шлюз Одиночного Экстренного Реагирования (`single_symbol`)
Внутри обоих конвейеров (`sync_signals_yf.py` и `sync_fundamentals_yhoo.py`) зашит сквозной шлюз быстрого реагирования. Аргумент `single_symbol` мгновенно отключает любые ночные лимиты, пачки и `LIMIT 20`. При залёте новой бумаги из Телеграм-канала система точечно за 3 секунды наполняет новичка под ключ котировками, RSI, MACD и 18 фундаментальными мультипликаторами.

### 6.4 Скрипты Первичной «Холодной» Миграции (Развертывание с нуля)
Для мгновенного развертывания ядра на абсолютно пустой СУБД используются два специализированных пакетных мигратора:
1.  **`/root/UPort/mass_init_passports.py`** — принудительный массовый запуск паспортистки на весь Universe (первичное создание JSONB-карт `ticker_name_map` и простановка MIC).
2.  **`/root/UPort/mass_init_fundamentals.py`** — пакетный докачиватель фундаментала. Нарезает базу на пачки по 30 акций с «Рейт-лимит щитом» (пауза 40 секунд между эшелонами) для безопасного обхода блокировок Yahoo при первом старте.
