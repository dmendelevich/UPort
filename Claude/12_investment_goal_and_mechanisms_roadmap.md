# Цель инвестирования и дорожная карта недостающих механизмов (согласовано 2026-08-02)

Тема выросла из разговора про слом тренда: чтобы понять, насколько он важен и как его калибровать, сначала понадобилось явно сформулировать общую цель инвестирования и сверить с ней текущую архитектуру. Метод, каким шли — от общего к частному: цель → модель → сверка модели с реальными данными → инвентаризация недостающих механизмов → порядок работы. Повторять для похожих тем (см. тот же приём в [11_asset_lifecycle_and_plan.md](11_asset_lifecycle_and_plan.md)).

## Цель (сформулирована пользователем 2026-08-02)

Устойчивая прибыль ~15% годовых при минимально разумном риске. Без спешки, короткие спекулятивные сделки не интересуют. Модель — «ядро + сателлит»: значительная часть капитала в долговременных активах с доходностью 7-10% (уровня S&P), меньшая часть — в более рискованном, но эффективном режиме, вытягивающем общую доходность до целевой.

Формула для проверки: `C×8% + (1−C)×R_satellite = 15%`, где C — доля капитала в спокойной части. Чем больше C, тем выше требуемая доходность рисковой части (например, при C=70% нужно `R_satellite≈31%` годовых, при C=50% — `≈22%`). Пропорция явно не зафиксирована числом — ориентир, не жёсткий норматив.

## Архитектура уже реализована правильно — сверка, не новая задача

Изначально показалось, что П10 (90% Револьверная) и П136 (65% Консервативная + 30% Трендовая) — это разрыв с моделью «ядро+сателлит» (ни один портфель не выглядит как «ядро+сателлит» сам по себе). Пользователь поправил: оба портфеля разделены только по техническим причинам брокера и должны рассматриваться как единая система — ядро (Консервативная) физически живёт только в П136, освободившийся в П136 капитал работает в более эффективной, но рискованной Трендовой, а самая рискованная Револьверная сосредоточена в П10.

Механизм для этого уже есть и работает: `strategies.is_screening_active` (реализовано и протестировано 2026-08-01, см. `BACKLOG.md`, «Сделано») — каждый портфель физически имеет ВСЕ содержательные стратегии, но пассивные (`is_screening_active=false`) не участвуют в подборе новых кандидатов, только сопровождают уже держимые позиции. Действий не требуется, архитектура соответствует цели.

## Шесть направлений — инвентаризация недостающих механизмов

Сгруппировано по тому, чем каждый пробел угрожает капиталу, не по хронологии обнаружения.

**Группа 1 — качество отдельной сделки (вход/выход не туда/не тогда):**
1. **Слом тренда / подтверждённый разворот — ✅ реализовано и протестировано 2026-08-02** (`signal_ema20_streak_days`, см. `BACKLOG.md` «Сделано» п.32). Было: ложные докупки в падающий нож (пример MU) и случайные выходы по шуму (VRTX/BA).
2. **Частичный выход по лестнице — ✅ пересмотрено и закрыто 2026-08-02, БЕЗ лесенки** (см. `BACKLOG.md` «Сделано» п.33). Разбор «от инвестора» по `human_philosophy` каждой стратегии показал: лесенка на выходе не нужна НИ ОДНОЙ из трёх — оправдана только там, где сама суть стратегии — усреднение (вход Консервативной, уже сделано п.1). Револьверная/Трендовая — однострельные и на входе, и на выходе по замыслу («без усреднений вниз» / «жёсткий стоп»). Вместо лесенки — доточено бинарное дерево выхода Револьверной (перенос ЦЕЛИКОМ в Трендовую вместо частичной фиксации, ранний выход при подтверждённом сломе до цели).
3. **Гэп через несколько ступеней сразу — ✅ закрыто БЕЗ нового кода, 2026-08-02** (см. `BACKLOG.md` «Сделано» п.35). Исходная опасность ("гэп вниз, слепая докупка по формуле") устранена побочным эффектом `require_confirmed_reversal` (п.1) — сразу после гэпа разворот заведомо не подтверждён, значит докупка физически не может сработать до того, как падение реально остановится. Отдельный механизм паузы не нужен.
4. **«Сдаться», если разворот так и не пришёл» — ✅ реализовано вместе с п.1** (тот же примитив «подтверждённый разворот», `PositionExitEvaluator._check_conservative_exit`, `rules_config.tactic_give_up_days`).

**Группа 2 — структура капитала (доли разъезжаются со временем):**
5. **Ребалансировка между стратегиями** — `strategy_share_pct` не проверяется на факт. `BACKLOG.md` п.4.
6. **Ребалансировка внутри стратегии по весу бумаги** — нет ни механизма, ни поля в схеме. `BACKLOG.md` п.4 (второй абзац).

**Группа 3 — портфель целиком:**
7. **Рыночный предохранитель на обвал** — точечные правила по бумагам могут не успеть при обвале всего рынка. `BACKLOG.md` п.3, не начато.
8. **Портфельный риск/просадка не измеряется и не ограничивается** — сегодняшние лимиты (`portfolio_max_asset_pct`/`portfolio_max_sector_pct`) защищают от концентрации, не от просадки портфеля целиком. Найдено 2026-08-02 при разборе цели, в бэклоге отдельно не зафиксировано.

**Группа 4 — калибровка (летим вслепую без этого):**
9. **Измерение фактической эффективности стратегий** — ни у одной из трёх нет посчитанной реальной доходности/просадки, есть только параметры, которыми на неё надеемся. Без этого нельзя проверить, движемся ли к 15% годовых. Упоминалось в связке с NFLX (`BACKLOG.md`, разбор около п. с журналом рекомендаций/бэктестом), решение не принято.
10. **Технический блокер для п.9**: `order_pipelines_unique_run` — жёсткий уникальный индекс, не даёт завести второй цикл по бумаге+стратегии после завершения первого → без истории циклов нечем измерять эффективность. `BACKLOG.md` п.37, решение зафиксировано (частичный индекс), реализация не начата.

Итого не 10 независимых тем, а **шесть содержательных направлений**: (а) слом тренда + «сдаться» [п.1+4], (б) частичный выход [п.2], (в) гэп-обработка [п.3], (г) двойная ребалансировка [п.5+6], (д) рыночный предохранитель + портфельный риск [п.7+8], (е) измерение эффективности [п.9, после починки п.10].
