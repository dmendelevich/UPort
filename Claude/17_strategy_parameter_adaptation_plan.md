## Два вопроса, заданных пользователем в конце сессии 2026-08-08 (с ответами)

1. **«Слом тренда Трендовой проверяется в течение 3 дней?»** — Да, подтверждено в коде: `settings.TREND_REVERSAL_CONFIRM_DAYS = 3`. Три торговых дня подряд цена держится ниже EMA20 → подтверждённый слом (используется в выходе Трендовой, входе шагов 2/3 Консервативной, «сдаться» по зависшей ступени).

2. **«Лимитный ордер по оптимальной цене вместо рыночной — мы это куда-то включили в план?»** — Нет, это `BACKLOG.md` **№87**, открытый вопрос, зафиксирован при обсуждении Индексного ядра, **не в этом плане, решение не принято**. Предварительный разбор по стратегиям уже есть (см. №87 целиком): для Индексного ядра market — правильно, менять не нужно (market timing на диверсифицированном индексе проигрывает); для Трендовой — противоречит философии «вход на разгоне»; для Консервативной — идея имеет БОЛЬШЕ ВСЕГО смысла (вход и так завязан на просадку, лимитная заявка у более точного уровня, нормализованного по волатильности, может дать точку входа лучше момента срабатывания сигнала); Револьверная не разобрана подробно. Механизм для лимитных заявок ПОЗЖЕ (шаги 2/3 лесенки Консервативной) уже есть и работает — вопрос именно про САМ ПЕРВЫЙ вход.

## Готово к реализации — принцип полностью согласован, можно кодить сразу

**Все три пункта ниже реализованы и протестированы 2026-08-08, см. `Claude/BACKLOG.md` №93.**

### 1. Консервативная — буферная зона дисконта (находка Q, только что согласована 2026-08-08)
Заменить в `analytics/analytics_utils.py::_score_conservative`:
```
было:  signal_price_to_sma200_pct < 0.00
стало: signal_price_to_sma200_pct < K × signal_daily_volatility_pct,  K = 2.5
```
Нижнюю границу (глубина просадки) не трогать. На сегодняшних данных добавляет 10 компаний к пулу кандидатов (MSCI/NEM/ORLY/CBOE/CDNS/CBRE/PGR/MCK/EME/GOOGL), пул растёт с 30 до 40. `K` — константа в коде или в `rules_config`, решить при реализации (по аналогии с другими K-множителями в системе — обычно в коде, не в `rules_config`, если не привязан к конкретной стратегии/портфелю).

### 2. Консервативная И Револьверная — FCF NULL-баг (находка D)
`idea_require_positive_fflow_bool` читает `NULL` как `0.0` и жёстко проваливает, в отличие от ROE/долга/CAGR/роста выручки, которые корректно используют `_na_or_check` (`NULL` = «неприменимо», не провал). Применить тот же хелпер к FCF-проверке в ОБОИХ `_score_conservative` И `_score_revolver`. Живой эффект у Револьверной прямо сейчас (на момент находки): 4 из 27 кандидатов неверно проваливались.

### 3. Револьверная — `NULL` в `target_mean_price` (находка Д/E)
`upside_pct` при `target_mean_price IS NULL` читает целевую цену как $0 → ранжирование получает **-100%** («аналитики ждут падения до нуля»). Исправить: трактовать `NULL` как «неприменимо» — либо исключать тикер из ранжирования по этому критерию (вернуть `None`/пропустить), либо использовать нейтральное значение вместо -100%. Точная трактовка (исключить vs нейтральное значение) не финализирована — решить при реализации, не критично, куда важнее просто не давать -100%.

**Решено при реализации 2026-08-08**: нейтральное значение (`upside_pct = 0.0`), не исключение из пула — остальной фундаментал тикера остаётся валидным основанием для идеи, даже если аналитики его не покрывают.

## Не забыть при реализации

- Каждое изменение — по обычной процедуре: обсудить принцип → согласовать → код → тест послойно (прямой вызов на реальных данных, мок-хэндлер, `restart_uport.sh`, реальное сообщение в Telegram) → зафиксировать в `BACKLOG.md`.
- После каждого фикса имеет смысл заново прогнать полный `screen_universe_for_strategy` по затронутой стратегии на реальных данных и посмотреть на РЕЗУЛЬТАТ глазами инвестора — тем же методом, каким все эти находки и были найдены (см. предисловие `16_selection_logic_audit.md`) — чтобы не пропустить, что фикс одного гейта не открыл новую проблему в соседнем.
- Пункт G (сектора) логически связан с Индексным ядром — если будешь делать G, свериться с `15_index_core.md` и реальным состоянием `strategies` (`system_key='INDEX_CORE'`, id известны в БД) перед кодом.
