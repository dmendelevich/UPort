Нужен экран, где можно менять доли нескольких стратегий портфеля согласованно. *(зафиксировано 2026-07-21)*

12. **`BEGIN`/`ROLLBACK` отдельными вызовами `execute_query()` не дают реальной транзакции.** `uport_ai_gateway.py` открывает новое `psycopg2.connect()` на каждый HTTP-запрос — поэтому `db_sys.execute_query("BEGIN;")` в одном вызове и `db_sys.execute_query("ROLLBACK;")` в другом работают в РАЗНЫХ соединениях и не связаны друг с другом; всё, что между ними, коммитится по факту, "откат" — иллюзия. Обнаружено на практике: `test_strategy_sync.py` оставил в БД реальные тестовые строки (`strategies.id=999`, `assets`, `strategy_assets`) несмотря на финальный `ROLLBACK` — вручную вычищено 2026-07-21. Используется (ошибочно) в `test_strategy_sync.py` и `test_bot_utils.py`; в боевом коде такого паттерна нет (`bot_utils.py:execute_virtual_transfer` шлёт `BEGIN;...;COMMIT;` ОДНОЙ строкой в ОДНОМ вызове — это безопасно). Нужно почистить оба теста (переписать на единый CTE/строку, как в `execute_virtual_transfer`, либо явно предупреждать, что откат не работает). *(зафиксировано 2026-07-21)*

## Сделано
1. **Универсальные view от tickers до состава стратегий** — создано 6 слоистых view (`v_listings_tickers` → `v_assets_full`/`v_watchlist_full`/`v_orders_full`/`v_order_pipelines_full` → `v_strategy_assets_full`), протестировано (без коллизий колонок, без fan-out, сверка с ручными запросами). См. [02_universal_views.md](02_universal_views.md). *(2026-07-20)*

2. **Связь `strategies.template_id → strategy_templates.id` + `system_key`.** У словаря `strategy_templates` появился обязательный уникальный смысловой ключ (`system_key`: `REVOLVER`, `CONSERVATIVE_ACCUMULATION`, `TREND_FOLLOWING`, `CASH_RESERVE`, `UNALLOCATED`). У `strategies` появилась обязательная (`NOT NULL`) ссылка `template_id`, все 7 строк проставлены (включая новую — недостающую буферную стратегию портфеля 1). Починен баг поиска буферной стратегии в `_get_unallocated_strategy_id` (`brokers_connectors/sync_strategy_asset_fb.py`) — раньше терял фильтр по `portfolio_id` из-за AND/OR по имени, теперь ищет через `JOIN` по `template_id`/`system_key`. Скрипт миграции — [`fix_strategy_template_links.py`](../fix_strategy_template_links.py). Протестировано: `test_strategy_sync.py` (поправлен под `NOT NULL`), портфель 1 → буфер id=7, портфель 2 → буфер id=6 (раньше оба указывали бы на 6), несуществующий портфель корректно бросает исключение, `v_strategy_assets_full` не пострадал. См. [03_strategies_and_templates.md](03_strategies_and_templates.md). *(2026-07-21)*

3. **Конфликт роутеров: глобальный перехватчик текста ломал ввод имени портфеля.** `bot_handlers/ticker_search.py` содержит `@router.message(F.text)` — ловит вообще любой текст без ограничения по FSM-состоянию, зарегистрирован в `uport_ai_bot.py` РАНЬШЕ `portfolio_admin`. Обнаружено пользователем вживую: ввод имени портфеля «ПМ» на Шаге 3 перехватывался ticker_search («Тикер должен содержать только латинские буквы...») вместо `portfolio_admin.process_name_text`. `backlog.py` со схожим FSM-вводом текста работал только благодаря более раннему порядку регистрации своего роутера — везение, а не защита. Системный фикс: `@router.message(StateFilter(None), F.text)` в `ticker_search.py` — перехватчик срабатывает только вне любого активного FSM-состояния, независимо от порядка роутеров. Протестировано напрямую через `HandlerObject.check()` на трёх сценариях (idle-чат, состояние создания портфеля, состояние бэклога) — конфликт исчез, регрессии для бэклога нет. *(2026-07-21)*

INSERT ... RETURNING`). Кнопки везде передают числовые ID (добавлены поля `user_id`/`broker_id` в `MenuAction`, `bot_handlers/common.py`).
